# ETF Atlas integration contract
Standalone new app. Root D:/storm/life/etf-atlas. No edits to Hermes or sibling apps. Data is generated and ignored in git, published with Pages artifacts. Source code feature branch + PR/CI then merge. No fabricated data.

## Wire schema (schemaVersion 1)
public/data/market.json = {schemaVersion:1, generatedAt: ISO UTC, instruments:[Instrument], failures:[{id,error}], methodology:string[]}
Instrument = {id:string, symbol:string, name:string (Chinese), country:'CN'|'US'|'AU' (listing market), kind:'etf'|'index', benchmark:string, currency:'CNY'|'USD'|'AUD', sourceUrl:string, historyUrl:'data/history/<id>.json', firstDate:'YYYY-MM-DD', lastDate:'YYYY-MM-DD', count:number, status:'fresh'|'stale'|'unavailable', close:number|null, dailyChange:number|null (fraction), cashYield:number|null (fraction TTM cash / last close), dividendStatus:'available'|'unavailable'|'no-distributions', frankingRate:null|number, returns:{price:{'1m':fraction|null,'3m':...,'6m':...,'1y':...,'3y':...,'5y':...,'10y':...},total:{same}}, error?:string}
Requested ranking periods are 1, 3, 6 months and 1, 3, 5, 10 years. Implement all seven, plus ALL for chart only; daily change is a separate column.
public/data/history/<id>.json = {id, sourceUrl, retrievedAt, adjustment:'provider-adjusted-close'|'split-normalized-price'|'none', bars:[{date:'YYYY-MM-DD',open:number|null,high:number|null,low:number|null,close:number,adjustedClose:number|null,volume:number|null,rawClose?:number,rawOpen?:number,rawHigh?:number,rawLow?:number}], dividends:null|[{date:'YYYY-MM-DD' (ex date),amount:number,rawAmount?:number}], splits:[{date,ratio:number,effectiveDate?:string}], coverage:{firstDate,lastDate,count,complete:boolean,reason?:string}}
Price comparisons must adjust ETF share splits/consolidations, not mistake changes in share units for gains/losses. CN provider raw trading OHLC must also be preserved for download. F10 fold dates can be after close; verify the actual effective trading session from prices rather than assume premarket. Splits do not themselves establish a dividend-adjusted total-return series.
If split evidence is unavailable, optional history.priceComparisonUnavailable=true suppresses price-return rankings AND chart comparisons; raw trading history remains downloadable. A successful initial release requires this not to affect the required ETF universe.
Freshness uses exchange sessions, holidays and close times, not just elapsed calendar days. Optional instrument fields `expectedLastDate` (YYYY-MM-DD), `freshUntil` (explicit-zone ISO UTC next completed-session boundary) and `calendar` identify the validated latest completed session and next expiry. Clients honor expiry even on cached snapshots, preserve stale/unavailable states, and use the legacy five-day rule only for snapshots without calendar metadata. A long exchange holiday is not itself stale pricing. Publication requires strict fresh validated prices for all instruments and retains the previously deployed artifact on failure. Scheduled refresh runs twice every calendar day, even when exchanges are closed.
Unknown dividend events are null, not an empty array. An empty array is reserved for positively validated no distributions. Price index adjustedClose is null unless the symbol is an actual total-return index; Yahoo adjclose alone does not establish this.
returns use end instrument lastDate anniversary minus calendar months/years; baseline on or before target <=10 calendar days tolerance, history too short=null. Ratios NOT percentages. price bars provider split normalized if Yahoo, explain not historical nominal before split. total only if adjustedClose truly available, no guessing.
Only completed exchange sessions, no current intraday bars. Unknown dividend/franking=null never 0. TTM full 12 calendar months at lastDate; insufficient one year = null. For Chinese dividend events unavailable fallback=null; do not promise all dividends. CN prices full Eastmoney or Tencent annual pagination if Yahoo lacks data. Independently load index history rather than synthetic backfill. Yahoo requests must specify interval=1d and verify granularity and firstTradeDate; period1=0 is sufficient for post-1970 ETFs, but old index histories require a negative epoch to avoid truncation at 1970. Negative epoch conversion must work on Windows using arithmetic from the UTC epoch.

## Latest closing-field recovery
Full history remains the validated primary `interval=1d` series with symbol, currency and first-history anchor evidence. If its existing latest expected completed-session row alone lacks closing fields, a single-record recovery is allowed only from independently corroborated genuine closing observations. The minute source must provide an exact exchange-close timestamp; the secondary endpoint's appended current-day snapshot must match its regularMarketTime within 60 seconds after that same close, listing identity/currency, expected day and minute closing price. Record source URLs, granularities, timestamps, missing fields and supplied values. Use explicit supplied adjustedClose only, never guess it equals close. Do not convert weekly candles or replace valid daily values, and preserve strict failure/old-deployment retention whenever evidence is insufficient.
